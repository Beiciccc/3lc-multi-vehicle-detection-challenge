## Overview

Multi-class vehicle detection in traffic-style images. Labels are **axis-aligned bounding boxes** in **YOLO format** (class index + normalized center x, center y, width, height).

**Classes** (IDs 0-3, order must match `dataset.yaml`):

| ID | Name |
|----|------|
| 0 | truck |
| 1 | car |
| 2 | van |
| 3 | bus |

## Splits

| Split | Contents | Labels? |
|-------|----------|---------|
| **Train** | Images + YOLO `.txt` label files | Yes |
| **Val** | Images + YOLO `.txt` label files | Yes |
| **Test** | Images only | No (held out for leaderboard) |

## Directory layout (starter bundle)

```
competition_starter/
├── config.yaml              # Paths + hyperparameters - edit here
├── dataset.yaml             # YOLO paths (train/val/test under data/)
├── sample_submission.csv    # Authoritative row ids + image_ids
├── verify_setup.py          # Pre-flight environment check (run first!)
├── register_tables.py
├── train.py
├── predict.py
├── README.md
└── data/
    ├── train/
    │   ├── images/          # *.jpg or *.png
    │   └── labels/          # one .txt per image
    ├── val/
    │   ├── images/
    │   └── labels/
    └── test/
        └── images/          # no labels/ folder for participants
```

`dataset.yaml` uses `path: .` and points splits at `data/train/images`, `data/val/images`, `data/test/images`  all relative to the starter folder.

## Label format

Each `.txt` file contains one line per object:

```
<class_id> <x_center> <y_center> <width> <height>
```

All coordinates are **normalized** to image dimensions (values in [0, 1]). Empty `.txt` files may appear for images with no labeled objects.

## Image format

JPG or PNG as provided. Resolutions vary. The **scoring system** converts your **normalized** YOLO coordinates in `prediction_string` to pixel coordinates using each image's width and height  you do not submit image dimensions.

## Key files

| File | Purpose |
|------|---------|
| `dataset.yaml` | YOLO dataset config: paths, `nc`, class `names` |
| `config.yaml` | Starter settings: table names, hyperparameters, predict options |
| `sample_submission.csv` | Authoritative schema: `id`, `image_id`, `prediction_string` |
| `verify_setup.py` | Pre-flight check: Python, packages, GPU, data files |
| `register_tables.py` | Register train + val in 3LC (not test) |

| `predict.py` | Inference on test → `submission.csv` |
| `README.md` | Starter kit quick-start and troubleshooting |

## `sample_submission.csv`

One row per test image. Columns: `id`, `image_id`, `prediction_string`. Replace `prediction_string` with your model output; keep `id` and `image_id` exactly as provided. Full encoding rules: **[Evaluation](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/evaluation)**.

## Goal

Predict **axis-aligned bounding boxes** and **class** for **on-road vehicles** in each image.

**Classes** (IDs 0–3, must match `dataset.yaml` in your download):

| ID | Class |
|----|-------|
| 0 | truck |
| 1 | car |
| 2 | van |
| 3 | bus |

You are scored on **mAP@0.5** on a **hidden test set**. You receive **test images only** - no test labels.

## Data splits

| Split | What you get | Labels? | Role |
|-------|-------------|---------|------|
| **Train** | Images + YOLO `.txt` | Yes | Training; register as 3LC **train** table |
| **Val** | Images + YOLO `.txt` | Yes | Validation metrics; Dashboard review and optional label fixes |
| **Test** | Images only | No | Run `predict.py` → `submission.csv` → Kaggle upload |

For file counts, image format, and folder layout see **[Dataset Description](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/data)**.

## Data-centric workflow

This is the **iterative loop** at the heart of the competition:

### 1. Environment

Set up Python, PyTorch, and `3lc-ultralytics` per **[Environment Setup](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/environment-setup)**. Log in with `3lc login`. Start `3lc service` when you want to use the Dashboard. Then run `python verify_setup.py` to catch any problems before proceeding.

### 2. Register tables

```bash
python register_tables.py
```

Creates **train** and **val** 3LC Tables (idempotent - does not overwrite). **Test** images stay on disk only; they are **not** registered in 3LC. Paths and table names come from `config.yaml`.

### 3. Train

```bash
python train.py
```

Trains **YOLOv8n from scratch** (per **[Rules](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/rules)**). Produces:

- Weights under `runs/detect/<run_name>/weights/best.pt`
- A **3LC Run** with per-image predictions and metrics on **train** and **val**

### 4. Analyze in the Dashboard

Open [dashboard.3lc.ai](https://dashboard.3lc.ai) (with `3lc service` running). In the latest Run:

- Filter by **confidence**, **IoU**, **FP/FN** to find wrong labels, missing boxes, or duplicate annotations.
- Use **embeddings** (if enabled in `config.yaml`) to spot clusters of similar/problematic images.
- See **[FAQ → "How to spot label issues"](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/faq)** for specific filter recipes.

### 5. Improve data

Edit labels in the Dashboard where **[Rules]https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/rules)** allow. Each edit creates a new **table revision** - your data is versioned, never destroyed.

### 6. Retrain

```bash
python train.py
```

The starter calls `.latest()` on each table, so it **automatically** picks up your newest revisions.

### 7. Predict & submit

```bash
python predict.py
```

Reads `sample_submission.csv`, runs inference on `data/test/images`, writes `submission.csv`. Upload to Kaggle. CSV format: **[Evaluation](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/evaluation)**.

### 8. Iterate

Repeat steps 4–7. Better data → better mAP.

## Competition-specific rules

### Task

- **Multi-class object detection** with **four** vehicle classes (see **[Description](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/description)** / `dataset.yaml`).
- Submissions: **CSV** with columns `id`, `image_id`, `prediction_string`  format in **[Evaluation](https://www.kaggle.com/competitions/3-lc-multi-vehicle-detection-challenge/overview/evaluation)**.

### Model and training constraints

- **Architecture:** **YOLOv8n only**. The official `train.py` is locked to YOLOv8n and **trains from scratch** (`yolov8n.yaml`, random initialization - no COCO or other pretrained checkpoints). Using larger YOLO variants, other architectures, or replacing the training entrypoint with an unapproved script is **not allowed**.
- **Input size:** 640 px (default in `config.yaml`).
- **Hyperparameters:** May be tuned within `config.yaml` (learning rate, augmentation, epochs, etc.).
- **Prohibited techniques:** Model ensembling, test-time augmentation (TTA), pseudo-labeling, knowledge distillation, or any method that effectively circumvents the single-model constraint.

### Data use

- **Train / val:** Use only the provided data for training and local validation.
- **Test:** Images only do not attempt to obtain or use leaked labels.
- **External data / images:** Not allowed unless an explicit exception is published by the organizers.
- **Pretrained weights:** **Not allowed.** Training must start from random initialization.

### 3LC

- **3LC** is required for the prescribed workflow: register **train** and **val** Tables, run training integrated with 3LC Runs, and use the Dashboard for the data-centric loop.
- **Test** images are **not** registered in 3LC; inference uses `predict.py` on local test files.
- Participants must use their own **3LC account** and API key.

### Teams and submissions

- **Team size:** up to 4 participants.
- **Submissions:** 3 per day maximum.
- **Final selection:** Choose up to 2 submissions for final judging (per Kaggle settings).

### Timeline

- **Start / end / merger deadline:** As shown on the competition **Timeline**.

### Evaluation form (if applicable)
